## G1 场景范围确认

进入条件：S2 已通过，场景清单已生成。

向用户确认：

- 本期与非本期范围是否正确。
- 是否遗漏关键正常、异常或管理场景。
- 场景粒度是否围绕业务目标，而不是页面或接口。
- P0/P1/P2 优先级是否正确。
- 重复、重叠或相互矛盾的场景如何处理。

批准记录包含确认人、决策说明和已核对的场景清单指纹。场景范围、优先级或其他已确认清单事实变化时，从 S2 重新核验并确认 G1。

## G2 业务与接口冲突确认

进入条件：S4 已通过；业务流程所需外部能力已有场景来源、接口索引和核验矩阵。此时不要求 SEQ 已生成。G2 同时记录接口事实和所引用本地接口文档的内容指纹。S5 允许回填 `used_by_sequence_ids`；接口事实或本地证据内容变化时回到 S4 重新确认。外部 URL 保留为核验来源定位。

向用户确认：

- `missing`、`partial`、`conflict` 接口是否有补充材料或替代方案。
- 字段、状态、认证、时限、回调、幂等和错误处理是否足以支撑业务。
- 系统责任边界是否被业务方与技术方接受。
- 哪些假设允许带风险继续。

G2 可以在存在非关键缺口时批准，但必须把接受风险写入 `open-items.json`。接口事实发生变化会使 G2 失效。

## G3 最终基线冻结

进入条件：

- S8 全局核验结果为 `pass`。
- 用户故事、场景、时序、接口和页面覆盖满足检查规则。
- 不存在状态为 `open` 的 critical/high 问题。
- 八类核心展示产物已经生成且不含草稿标记，包含独立功能清单。
- 每个 `FUNC-*` 均已填写版本、一级模块、二级模块、功能名称、功能说明和新增/迭代类型，并能追溯到用户故事、验收条件和业务场景。
- 按 SKILL.md 核心规则及 [功能拆分与范围标准](feature-granularity.md) 逐项复核业务对象、单一主操作、触发、完成结果与操作拆分归属；包含／排除范围、规则、异常、依赖、假设和迭代差异完整。独立的开通／停用／恢复／删除、查询／详情／导出、配置／发布／默认切换不能藏在一条管理包里。不能按页面／角色重复计 FUNC，也不把字段／技术调用当作独立功能。功能条目数不是标准功能点数或价格。
- 对 SC/FUNC 一一对应、功能名称为业务领域、说明并列多种操作的清单逐项复查；必须说明哪些操作独立成项、哪些是必要明细、哪些是复用入口。数量相同或标题含“与”只是线索，不以固定条数或关键词自动判语义正确。
- 功能清单视图包含完整范围与 AC 判据，并与当前 JSON 指纹一致；未知边界不能用空数组伪装为已确认。
- 每个本期用户故事、验收条件和业务场景必须由真实本期 FUNC 或经核验、实际承载的未变存量操作覆盖；关联需要 UI 场景的功能必须有页面承载，非 UI 功能允许没有页面。存量只沿合法当前 ACTION 与该场景的直接归属计覆盖，不能把记录声明的全部 US/AC/SC 一并放行；历史、候选、占位和必要界面明细不独立计覆盖。未决范围/责任及 critical/high 仍按原门禁阻断。
- 每个 in-scope 场景都存在经过结构与几何核验的泳道图，且关键分支在图中可见；布局核验必须确认节点不重叠、连线不穿节点、线段不共线叠压且端点贴合节点边界。
- 每个 `FLOW-*` 都在业务场景 HTML 图集中存在独立跨场景业务流程图；Markdown 编号步骤不能替代该图。
- HTML 中的 `FLOW-*` 业务流程图和 `SC-*` 泳道图必须包含本地 PlantUML SVG 和 `data-plantuml-render="pass"`；默认 `compare` 还保留折叠的原生核验证据。`SEQ-*` 则必须是唯一完整的原生 SVG，不能使用或混入 PlantUML；事实指纹与消息覆盖须匹配。引擎成功返回不等于视觉核验通过。
- 业务与时序图以桌面宽屏阅读核验：内容不受固定最大宽度挤压，目录默认折叠，窄图铺满可用宽度，宽图可横向滚动；等比缩放、适应宽度、100% 与全屏工具可用。建议覆盖 1440/1920/2560 宽度与一张超宽图；不增加移动端验收，不放松重叠、错位和标签完整性要求。
- 页面结构图已生成原生 SVG HTML（不使用 PlantUML），覆盖全部 PAGE；页面有有效 SC/SEQ 来源，S7 已完成 PAGE/ACTION 的本期 FUNC 或严格核验的存量操作归属。非 UI 需求无页面时图中明确展示无 UI，而不是强行创建页面。
- G1、G2 仍然有效。
- 如有 Wiki 输入，来源快照、版本、覆盖范围和缺口均已登记；`partial/missing/conflict` 已关联真实未决项，不能把未经核对的摘要提升为事实。原型消费的功能、规则、字段必须在结构化基线中，不得要求原型回查 Wiki。

## 可选候选图的验证边界

Mermaid 候选只供 S3 对比，不参与替代正式图的通过判定。其来源/源码/成品绑定必须一致；候选几何审计中的重叠、穿节点、叠压、标签错位、无法证明的形状或端点均阻止自动通过。正常正交交叉只作阅读复核提示，不自动当作业务汇合。依赖未安装、浏览器未运行或候选检查受阻必须保留明确状态；即使候选自动检查通过，人工视觉与业务确认仍未完成，不能批准 G3。说明和命令见 [Mermaid 候选绘图工具](mermaid-candidate.md)。

## 自动检查与人工判断边界

自动检查适合验证 ID、引用、文件存在性、功能必填字段、边界字段类型、版本差异、视图同步、修改类型、覆盖关系、接口来源、泳道布局几何、四类图按指定渲染策略的本地完整性与时序/页面事实指纹和草稿标记。人工判断负责功能最小性、拆分／合并及去重依据、模块归属、业务范围、语义正确性、流程合理性、业务图复杂分支及原生长时序的桌面可读性、风险接受和最终冻结。自动检查通过不等于业务确认完成。
