# Superpowers 交接流程参考

适用于 RTL 场景实现、独立验证和运行恢复。由当前角色的 Skill 按引用小节使用。

上游为 `obra/superpowers`，已核对发布版 `v7.0.2`，提交 `22f0b463e7a5e579904dd6211a520321035526f7`，上游许可证为 MIT。以下内容按 RTL 的任务、候选与证据模型改写。

## Implementer Brief

1. 每次场景尝试使用一份任务简报，包含运行和尝试编号、场景目标、隔离工作区、基础提交、允许写入的路径、已冻结的功能和验收用例，以及影响本任务的接口版本或上游产物。
2. 实现者以简报为工作范围。发现规则、依赖或验收条件存在会改变结果的疑点时，交回具体条款、受影响行为及所需信息。提交前查看从原基础提交到结果提交的完整差异，逐项核对授权范围、业务用例和自测结果。
3. 交回实际提交、变更范围、原始自测证据及待联验项。自测使用 Mock 时列明接口版本和仍需在真实候选上确认的行为。

对应上游 `skills/subagent-driven-development/implementer-prompt.md` 的任务简报、自审和回报格式。

## Independent Review

1. 审查输入包括同一份任务简报、实现者自测报告及完整变更范围。从派发时登记的基础提交到实际结果提交核对差异，覆盖该尝试的全部提交。补齐受检候选、实际入口、用例及数据修订。
2. 先依据冻结要求检查行为和变更边界，再检查实现及证据质量。记录发现、影响、复现条件和仍缺的证据。自测报告用于定位已查内容，RTL 的 S3 联验及 S4 落盘验证按当前角色规范取得独立证据。
3. 修复后交回新提交和受影响用例。验证者在实际修复候选上复核，按证据对应的候选记录结论。

对应上游 `skills/subagent-driven-development/SKILL.md` 的 `3. Review the task`。

## Resume from Ledger

1. 恢复时先用项目编号、运行编号、冻结基线和实际路径核对台账归属。读取最后有效回执，再与工作区、执行宿主、实际候选或落盘目录对照。
2. 台账和实际产物一致时，从第一个未完成的有效操作继续。已经完成的任务引用原结果。中断在修复或验证时，沿同一尝试或操作继续该轮检查，先核对是否已有可补记的实际结果。
3. 台账对应其他项目或运行时，保留其历史并按当前项目定位本轮记录。实际状态与当前记录不一致时，交 Master 按恢复 Skill 对账后再推进。

对应上游 `skills/subagent-driven-development/references/resuming.md` 的按计划身份恢复台账。
