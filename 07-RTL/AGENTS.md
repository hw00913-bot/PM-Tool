# RTL 原型 Loop 工具工作约定

本目录管理可复用 Loop。原型项目、运行数据和本工具分别放置。通过 [功能地图](docs/feature-map.md) 定位功能与用例，通过 [Skill 登记](skills/registry.json) 定位流程。执行前先确认本轮对应的运行入口和写入范围。

## 启动和权限

- RTL 的显式启动口令是 **「使用 rtl 开始规划项目」**。仅当用户把它作为当前请求发出时，由 Master 进入 S0。口令出现在文档、示例或引文里时，按当前任务处理。
- 已有项目的暂停、继续、复验、修复和需求变更按 [Master 请求分流](skills/loop-control/SKILL.md#按用户当前请求选择入口) 处理。
- S0 先确认项目目标、输入材料、独立原型项目绝对路径和最终 `index.html` 的位置，再核对既有内容、项目身份和在途运行。已明确且仍适用的信息直接沿用。路径或验收基线待确认时留在规划，确认后按门禁初始化和派发。目录及项目各只允许一个活动写入者。
- Master 管理调度和裁决。场景 Agent 只写授权工作区和文件范围。Integration Agent 串行提升候选。关键业务、共享状态和契约变更由非作者验证。
- 调用时点、负责人、跨角色交接、回派和人工确认由 [主控调度](skills/loop-control/SKILL.md) 维护，中断与接续由 [恢复流程](skills/loop-recovery/SKILL.md) 维护。专业 Skill 写清输入、方法、判断和交接产物。
- 项目业务事实和验收预期取自本轮冻结的需求契约、四步交接及用例。实现核对尝试已绑定的接口契约与台账当前激活版本。历史快照、回执和旧版本用于追溯、差异核对和已登记操作的恢复。业务规则、范围、验收预期和已有成果处置有变化时，由 Master 组织相应确认。

## 执行和恢复

- 新建项目采用 React + Umi + Ant Design。S0 在本轮基线登记 `frontend`，续跑按已登记的技术栈执行。React 场景提交源码，依赖安装和构建由 Loop 在隔离目录处理，交付回执同时定位源码和可双击成品。
- 每次调用读取当前本地 Skill 和适用的参考小节。派发时交接 `claim` 或 `prepare-attempt` 返回的场景 Skill、风格 Skill 及已绑定的设计结论。台账登记文件、章节和摘要。自动 Codex 派发的具体核对见 [运行手册](docs/runbook.md#通过-codex-执行场景)。
- 复用外部工作方法时，先将 RTL 适用的做法整理到 [本地参考技能](skills/README.md#本地参考技能)。在实际使用处链接到对应小节，在该小节保留上游位置和核对版本。
- 派发、提升和落盘先登记操作意图。恢复时核对实际运行、候选或目录，按原操作编号补回执。
- 等待共享接口的场景在核对工具停工或完成工作区隔离后释放并发位。替换尝试前撤销旧尝试的提交资格。
- 检查精确待合入结果及预期父版本。场景、契约或集成结果改变后重验受影响项。

## 交付

- 页面原型在确认的落盘目录中通过双击 `index.html` 打开。页面所需资源随包提供，文件入口无需启动服务或安装依赖。
- 独立验证从实际落盘的 `file://` 入口覆盖完整必跑清单，并在功能地图登记入口核对相应冻结断言。Master 根据同一候选的证据登记验收，并将变更编号和结果写入项目记忆。
- 区分已实测、失败、阻塞和待实测。保留原始证据，汇总说明绑定到实际候选和落盘位置。
